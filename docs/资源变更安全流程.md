# IaC资源变更安全流程

## 1. 为什么需要变更控制

生产环境中 Terraform 最大风险不是创建失败，而是误删除、误重建已有资源。

## 2. 变更流程

代码修改

↓

Terraform fmt

↓

Terraform validate

↓

Terraform plan

↓

人工检查 Change

↓

批准

↓

Terraform apply

↓

验证资源状态

## 3. Plan审核重点

重点关注：

- destroy 数量
- replace 操作
- 网络变化
- AKS变化
- 数据库变化
- IAM权限变化

生产环境原则：

出现 destroy / replace 必须人工确认。

## 4. 防止覆盖已有资源

措施：

- Terraform State 独立管理
- Resource Import
- Resource Lock
- 最小权限
- 定期 Drift 检测

## 5. 故障恢复

发生错误变更：

1. 停止继续 apply
2. 保存当前 state
3. 查看 Terraform plan
4. 恢复资源配置
5. 记录事故原因
